# AutoForgeRobot

An AI-driven code iteration toolkit that turns goals and reference code into editable, verifiable candidates.

## Core Features

- **AI tool loop** — read files, edit code, validate changes, and improve from feedback.
- **Reference learning** — reuse local source code and REA analysis with traceable origins.
- **Independent validation** — verify the exact code snapshot instead of trusting the model's claims.
- **Controlled execution** — run application checks through a Docker/Podman adapter.
- **Recoverable workflows** — pause and resume candidate iterations without blindly repeating interrupted operations.

## Quick Start

Requires Python 3.11+. Configure an OpenAI-compatible model using `AUTOFORGE_API_BASE`, `AUTOFORGE_MODEL`, and `AUTOFORGE_API_KEY` when required.

python autoforge/application_build.py --help

## Agent Streaming

Agent mode requests `text/event-stream` and persists `model_text_delta` and `model_tool_delta` records to `<output>/events.jsonl` as complete SSE records arrive. Readers can follow this UTF-8 JSONL file while the run is active; a partially written last line must be held until its newline arrives. Delta records are untrusted observations, **not executable tool requests**. Tool fragments are assembled by index, then require an accepted finish reason, `[DONE]`, valid call IDs/names/JSON, and the runtime's argument/permission checks before execution. No silent non-streaming fallback or model retry occurs.

The HTTP client retains explicit endpoint configuration, disabled proxies, forbidden redirects, a 60-second socket timeout and a 4,500,000-byte response budget. Streaming runs in an owned killable process: stop interrupts header and idle-read waits, not just the next received delta. Invalid/truncated/disconnected streams enter HOLD before dispatch. Private reasoning is neither persisted nor returned as evidence. Server usage counters are validated when present; missing counters are recorded unavailable, never fabricated or represented as bills.

## Durable Sessions and Controls

`application_build.py run --resume` resumes the same agent output with the same task, references, endpoint/model, controller code, builder identities, permissions and budget. A session checkpoint is committed after every tool result. Candidate writes remain isolated snapshots; source projects are never overwritten. Ambiguous in-flight validation remains BLOCKED; do not delete its marker to force a replay. Successful/cancelled terminal sessions do not call the provider again.

The run directory contains `session.json`, a recoverable `candidate.json` mirror, sequenced `events.jsonl`, and private `.control.json`. Keep the entire directory private: it contains source and the control capability. CLI clients obtain the token from that operator-owned capability file; do not send it to the model or put it in command-line arguments/logs.

```powershell
$env:AGENT_SESSION_CONTROL_TOKEN = (Get-Content '<run>/.control.json' -Raw | ConvertFrom-Json).token
python autoforge/agent_session.py control '<run>' pause --request-id pause-1
python autoforge/agent_session.py control '<run>' steering --request-id correction-1 --text 'Preserve the existing public interface.'
python autoforge/agent_session.py events '<run>' --after 0 --limit 100
```

`stop` cancels; `pause` permits safe continuation; `steering` increments the goal version and discards stale in-flight model actions; `follow_up` queues work until the current task boundary. Controls cannot enlarge tools, budgets or deployment rights. Capability expiration/revocation and session ownership are checked. Completed control request IDs are deduplicated.

Budget flags include `--max-turns`, `--tool-budget`, `--token-budget`, `--time-budget`, `--cost-budget-microunits`, and explicit input/output prices per million. Token reservation conservatively uses serialized UTF-8 bytes plus framing and requested output capacity; reservations are not refunded on failed requests. This is an enforceable dispatch bound, not an external provider billing guarantee. Model repeated no-progress failures HOLD. Long context compaction preserves goals/corrections, current source digests and a complete recent tool exchange; original messages are archived, not replaced as evidence.
